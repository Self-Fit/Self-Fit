# Self Fit 백엔드

Express + PostgreSQL + Prisma로 실제 계정·운동 기록·정정·첨부·알림을 저장합니다. API 계약은 [API.md](./API.md), 운동 집계 규칙은 [src/domain/index.js](./src/domain/index.js)에 있습니다.

## 로컬 실행

프로젝트 루트에서 실행합니다. Node.js 22.12 이상, PostgreSQL, 영상 검사용 `ffprobe`가 필요합니다. 영상 회귀 테스트에는 `ffmpeg`도 사용하며, 없으면 영상 길이 검사만 건너뜁니다(`FFMPEG_PATH`로 경로 지정 가능).

```sh
npm install
npm run setup
npm run dev
```

`setup`은 프로젝트 전용 PostgreSQL 시작, Prisma Client 생성, 마이그레이션 적용을 수행합니다. 학생이나 예시 활동 기록을 생성하지 않습니다. 기본 프런트엔드는 `http://127.0.0.1:5173`, API는 `http://127.0.0.1:4000/api`입니다. 프런트엔드 개발 서버가 `/api`를 프록시합니다.

이미 준비된 DB에서 백엔드만 실행하려면 루트에서 다음을 사용합니다.

```sh
npm run db:deploy --workspace backend
npm run start --workspace backend
```

`GET /api/health`의 `database: "ready"`가 DB 연결 성공을 뜻합니다. 운영 서버는 시스템의 실제 한국 날짜를 사용합니다. 날짜를 되돌리는 환경 변수나 HTTP API는 없습니다. 신규 활동 입력과 운동 독려는 각 챌린지의 활동일과 참여 상태를 기준으로 열립니다. 레거시 2026 챌린지는 기존 종료일인 2026년 9월 4일 이후 입력·독려가 닫히고, 기존 기록 조회와 정정 절차는 유지돼요.

## 챌린지 이관과 API 범위

챌린지 계약과 작업 단계는 [챌린지 안내](../docs/challenges/README.md), 요청·응답 및 검증 규칙은 [API 계약](../docs/challenges/api-contract.md)과 [공유 픽스처](../docs/challenges/fixtures/)를 참고해 주세요. 백엔드 phase 1·2는 챌린지 생성·조회·수정·게시·보관·초안 삭제·양식 복사, 참여자 선택·강제 등록·초대, 학생 수락·거절과 챌린지별 기록 API를 제공해요. 프런트엔드 화면 연결과 최종 UI 검증은 별도 단계예요.

마이그레이션은 기존 프로그램을 고정 ID `challenge-2026-self-fit`의 게시된 챌린지로 이관해요. `LEGACY_WEEKS`의 날짜·목표·단위·색·설명과 덤벨 종목을 그대로 보존한 12개 주차/82개 활동일을 만들고, 기존 `DailyRecord`를 이 ID로 백필해요. 기록의 고유 키는 `(challengeId,userId,date)`로 바뀌어 서로 다른 챌린지의 같은 날짜를 분리해요. 필수 학생은 `forced/active`, 참여 중인 선택 학생은 `invited/active`로 참여 정보를 백필하며, 다른 학생에게 참여 정보를 임의 생성하지 않아요. 새 DB에는 챌린지 정의만 만들고 계정·기록은 넣지 않아요.

이관은 기존 기록값·완료 주차·참여율·엑셀 실적을 바꾸지 않아야 해요. 배포 전 DB 백업을 보관하고, `_test` DB의 격리 스키마에서 빈 DB와 기존 기록이 있는 DB 모두 마이그레이션을 검증해 주세요. 회귀 테스트는 변경 전 도메인의 합성 데이터 기준과 변경 후 결과를 비교해요. 적재 스크립트는 `legacyChallengeId(db)`로 이관 대상 챌린지를 확인하며 항상 레거시 챌린지에만 기록을 넣어요. 운영 DB에 시드나 시연 데이터를 적재하지 마세요.

기존 `/program`, 학생 대시보드·기록 경로는 서버가 현재 챌린지를 해석해요. 학생은 active 참여 중 `active → upcoming → rest → 최근 ended` 순서, 교사는 게시된 챌린지 중 시작일이 가장 늦은 것을 선택해요. 교사 현황·참여율·엑셀·정정·학생 상세 조회는 `challengeId` 쿼리로 다른 챌린지를 지정할 수 있어요. `/program`은 기존 모양에 `challengeId`가 추가되고, 해당 JSON 교사 응답에는 `challenge`가 포함돼요. 명단은 계정 단위로 유지하며 성과 분모는 선택된 챌린지의 active 참여자만 포함해요. 새 명단의 필수 구분은 챌린지 자동 등록을 뜻하지 않으며, 챌린지의 강제 등록과 분리돼요. 기존 `User.participating` 값은 레거시 호환을 위해 유지하고, 챌린지 참여 판정에는 `ChallengeMembership`을 사용해요.

## 챌린지 참여 운영

교사는 게시된 챌린지에서 학번 ID 목록 또는 학년·반·대상 구분 필터로 인원을 골라요. 미리보기 API는 저장하지 않고 현재 참여 상태를 보여 줘요. 실제 등록은 선택한 학생 전체를 한 트랜잭션으로 처리하며, 이미 active인 학생과 없는 ID·교사 ID는 응답의 `skipped`에 이유를 남겨요. 참여자·미리보기 응답의 `User.participating`은 해당 챌린지의 active 여부를 보여 줘요. 명단의 필수·선택 구분·학년·반과 계정 자체는 변경하지 않고, 일반 명단 조회와 `/auth/me`는 기존 계정의 participating 값을 유지해요.

강제 등록은 즉시 `forced/active`가 되고, 초대는 `invited/pending`으로 시작해요. 학생이 수락하면 active, 거절하면 declined가 돼요. 교사는 거절한 학생을 다시 초대하거나 강제 등록할 수 있어요. 초대 발송·수락은 `enrollmentDeadline` 당일까지, 강제 등록은 `endDate` 당일까지 가능해요. 모두 서버의 한국 날짜를 사용하며, 종료·마감 후 요청은 오류로 거부해요.

참여자 제외는 행을 지우지 않고 removed로 바꿔요. 그 챌린지에 기록이 있으면 `HAS_RECORDS`로 제외를 거부하고, 다른 챌린지에만 있는 기록은 영향을 주지 않아요. 제외한 참여자는 다시 등록할 수 있어요. 참여자 목록은 기본적으로 removed를 숨기고 상태 필터로 확인할 수 있어요. 통계는 학년·반·대상·검색으로 고른 범위 전체를 집계하며, 목록의 상태·등록 방식 필터에는 영향을 받지 않아요. 등록 방식별 합계에서는 removed를 제외해요.

학생은 `/api/student/challenges`에서 현재 챌린지·참여 목록·수락 가능한 초대를 확인해요. 목록은 요약, 개별 상세와 대시보드는 주차·활동일을 포함한 전체 정의를 제공해요. 게시된 챌린지의 설명은 초대를 수락하기 전에도 볼 수 있지만, 기록 조회·입력·정정·첨부 변경은 해당 챌린지의 active 참여자만 가능해요. pending·declined·removed는 성과 분모에 포함하지 않아요. 기존 기록 경로와 새 `/student/challenges/:id/records...` 경로는 같은 처리 함수를 사용해요.

호환 경로 `/student/enroll`은 수락 가능한 초대가 하나면 그 초대를 수락하고 기존 `{user}` 응답을 유지해요. 초대가 없으면 기존 `403 ENROLLMENT_CLOSED`, 여러 개면 `409 INVITATION_SELECTION_REQUIRED`와 `details.challengeIds`를 반환해요. 여러 초대 중 하나를 임의로 수락하지 않으며, 클라이언트에서 선택한 `/student/challenges/:id/accept`를 호출해야 해요.

마이그레이션 당시 교사가 없었거나 초대한 교사 계정이 삭제됐다면 `Membership.invitedBy`는 `null`이에요. 존재하지 않는 교사 이름을 대신 만들지 않아요. 참여 변경·초대 수락·기록 입력·보관 처리가 겹쳐도 트랜잭션과 행 잠금으로 현재 참여 상태를 다시 확인해요.

## 실제 교사 계정 생성

교사 계정은 자동 생성하지 않습니다. DB 준비 후 터미널에서 실행하세요.

```sh
npm run bootstrap-teacher --workspace backend
```

본인의 로그인 ID와 이름, 비밀번호를 직접 입력합니다. 비밀번호와 확인 입력은 화면에 표시되지 않으며 로그에 남기지 않습니다. 비밀번호는 영문·숫자를 포함한 8~128자이고 로그인 ID와 달라야 합니다. Ctrl+C로 취소하면 계정을 만들지 않습니다. 교사 계정이 이미 있으면 덮어쓰지 않고 종료합니다.

자동화가 필요한 경우 `TEACHER_ID`, `TEACHER_NAME`, `TEACHER_PASSWORD` 환경 변수 또는 `studentNumber`, `name`, `password` 필드의 JSON 객체를 표준입력으로 전달할 수 있습니다. 비밀번호를 CLI 인수에 넣지 마세요. 표준입력 JSON은 전달한 필드에 한해 환경 변수보다 우선합니다. 명령 성공 시 비밀번호를 출력하지 않습니다.

학생은 교사 로그인 후 명단 화면에서 실제 명단으로 등록합니다. 엑셀은 먼저 검증하며, 교사가 등록을 실행해야 저장됩니다. 등록·초기화에서 발급한 개인별 임시 비밀번호는 해당 응답에서 한 번만 제공하며 서버는 해시만 저장합니다.

## 환경 설정

백엔드는 `backend/.env`를 읽습니다. 루트의 DB 도구가 만든 로컬 설정을 사용할 수 있습니다. 이 파일과 DB·첨부 폴더는 버전 관리하거나 웹 정적 폴더에 넣지 않습니다.

| 변수 | 용도 |
| --- | --- |
| `DATABASE_URL` | 실제 서비스 전용 PostgreSQL 연결 |
| `TEST_DATABASE_URL` | 이름이 `_test`로 끝나는 별도 테스트 DB 연결 |
| `APP_ORIGIN` | 허용하는 프런트엔드 origin. 기본 `http://localhost:5173`, 여러 주소는 쉼표 구분 |
| `HOST`, `PORT` | API 주소. 기본 `127.0.0.1`, `4000` |
| `STORAGE_DIR` | 공개 웹 경로 바깥의 첨부 저장 폴더 절대 경로 |
| `FFPROBE_PATH` | 필요할 때 지정하는 `ffprobe` 실행 파일 경로 |
| `FFMPEG_PATH` | 영상 회귀 테스트가 사용하는 `ffmpeg` 경로. 없으면 영상 길이 검사만 건너뜁니다 |
| `TRUST_PROXY` | 리버스 프록시 뒤에서 실제 접속 주소를 보도록 하는 Express trust-proxy 값(`1`, `true`, `loopback`, 주소 목록) |
| `NODE_ENV` | HTTPS 운영 환경에서 `production`으로 설정하면 세션 쿠키에 `Secure` 적용 |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` | 웹 푸시를 실제 사용할 때 운영자가 지정하는 키와 연락 URI |

로그인 실패는 계정당 15분에 10회, 접속 주소당 300회까지 허용하며 성공한 로그인은 세지 않습니다. 학교처럼 한 공인 IP를 공유하는 환경에서도 한 명의 실패가 다른 사람을 막지 않습니다. 프록시 뒤에서는 `TRUST_PROXY`를 설정해야 주소 단위 제한이 실제 클라이언트를 봅니다.

세션은 PostgreSQL에 저장하고 브라우저에는 HttpOnly·SameSite 쿠키만 제공합니다. 세션은 8시간 후 만료됩니다. 비밀번호 초기화는 학생의 모든 세션을 폐기합니다. 본인 학생과 총괄 교사만 첨부를 읽을 수 있으며 경로를 알아도 권한 검사를 거칩니다.

사진은 기록당 3장/각 10MB, 영상은 1개/100MB/60초까지입니다. 파일 내용을 검사하고 영상 길이는 `ffprobe`로 확인합니다. 당일 권한 확인을 통과해 시작한 업로드는 자정을 넘어 끝나도 같은 요청을 마무리할 수 있습니다. 기한 후 새로 시작하는 업로드·삭제는 거부됩니다. 업로드가 끝나기 전에 챌린지가 보관되거나 참여가 제외되면 저장을 거부하고 임시 파일을 정리해요. 파일 실패는 이미 저장된 운동 기록을 취소하지 않습니다.

명단 XLSX는 5MB까지 받으며 압축 해제 총량도 50MB로 제한합니다. 실제 셀의 수식·링크는 명단 값으로 가져오지 않습니다. 내보내기의 이름·학번·사유는 수식이 아닌 텍스트 셀로 저장합니다. 운영 첨부와 기록의 자동 삭제·보관 기간은 설정하지 않았습니다.

## 알림과 푸시

앱 안 알림은 웹 푸시 설정 없이 작동합니다. 운동 독려는 한국 시간 20시 이후 게시된 각 챌린지의 활동일·active 참여·주간 완료·입력 상태·주말 설정을 확인해요. `reminder:<challengeId>:<userId>:<date>` 이벤트 키로 챌린지별 학생·날짜마다 한 번만 생성해요. 이관 전 이벤트 키는 과거 이력으로 남기고 다시 발송하지 않아요. 정정 처리 알림은 챌린지 종료 후에도 남아요.

초대·재초대는 `invitation:<membershipId>:<invitedAt ISO>` 키로 초대 알림을 만들고, 강제 등록은 `enrollment:<membershipId>` 키로 등록 알림을 만들어요. 두 알림의 `data`에는 `{challengeId,membershipId}`가 들어가요. active 학생을 중복 등록해도 새 알림을 만들지 않고, 같은 참여 행을 제외했다가 다시 강제 등록하면 기존 등록 이벤트 한 건을 유지해요. 교사 정보가 없는 레거시 참여를 이관할 때에는 초대 알림을 임의 생성하지 않아요.

실제 휴대폰 푸시를 운영하려면 운영자가 VAPID 키·연락 URI를 정하고 위 세 변수를 모두 설정한 뒤 서버를 재시작합니다. 키를 임의 생성하거나 연락처를 추정해 설정하지 않습니다. 학생이 브라우저 알림을 허용하고 구독해야 전달할 수 있습니다. 아이폰은 홈 화면에 추가한 웹앱 흐름을 사용합니다. [WebKit 공식 안내](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)

푸시 실패는 같은 앱 알림 이벤트에서 최대 5회 재시도합니다. 성공한 구독에는 재시도를 생략하며 서비스 워커는 이벤트 ID를 알림 태그로 사용합니다. 만료된 구독은 제거합니다. 현재 VAPID가 미설정이면 실제 푸시 수신은 검증된 상태가 아니며, 앱 안 알림과 이벤트 생성·중복 방지는 별도로 검증할 수 있습니다.

운동 독려는 실제 기기로 보내기 직전에 조건을 다시 확인합니다. 그사이에 챌린지를 보관했거나 참여가 해제됐거나 주간 목표·당일 목표를 채웠거나 날짜가 지났으면 대기 중인 독려 푸시를 취소합니다. 앱 안의 과거 이벤트는 보존하며, 초대·강제 등록·정정 결과 알림은 이 운동 독려 제한을 적용하지 않아요. 초대·등록 푸시에는 `data`와 `/mobile/challenges` 클릭 URL을 전달하고, 나머지는 `/mobile/notifications`를 사용해요. 현재 프런트엔드 서비스 워커는 전달한 URL을 사용하지 않고 `/mobile/notifications`를 열어요. `/mobile/challenges`로 이동하도록 연결하는 작업은 프런트엔드 통합 범위이며, 백엔드 테스트는 전달 데이터와 URL까지만 검증해요.

## 테스트

루트에서 실행합니다.

```sh
npm test
npm run test:integration --workspace backend
```

도메인 테스트는 DB 없이 동작합니다. 통합 테스트는 `TEST_DATABASE_URL`이 있을 때만 실행하며 DB 이름의 `_test` 접미사를 강제합니다. 실행마다 임의의 별도 스키마와 임시 첨부 폴더를 만들고 마이그레이션을 적용한 후 정리합니다. 테스트용 계정·활동은 그 스키마 안에만 생성합니다. 운영 DB에 테스트 명단이나 시연 데이터를 넣지 않습니다.

통합 테스트는 인증·역할 권한, 첫 비밀번호 변경, 임시 비밀번호 초기화와 세션 폐기, 실제 종료일 제한, 정정 전후 값·이력·낙관적 충돌, 명단 검증/등록, 비공개 첨부·60초 영상 검사, 알림 중복 방지, 엑셀 의미 보존을 확인합니다. 챌린지 회귀는 빈 DB·기존 기록 마이그레이션, 레거시 집계·원본 지문 보존, 같은 날짜의 챌린지별 분리, 강제 등록·초대·수락·거절·재초대·제외, 마감과 동시 요청, active 분모, 알림 두 종류와 푸시 게이트 예외, 공통 픽스처 응답 키를 검증해요. 당일 입력 회귀만 테스트 프로세스의 시계를 가짜 시각으로 제어하며 실제 서버의 날짜 기능을 변경하지 않습니다.

## 학생 체력등급 반영

체력등급은 학년과 별도이며, 명단에는 확인된 가장 최근 학년도의 2학기 등급을 표시합니다. 학생 상세에는 학년도·학기별 이전 평가를 함께 제공합니다. 등급 선택은 챌린지 참여자 미리보기 조건일 뿐이며, 실제 강제 등록은 교사의 확정 동작으로만 실행됩니다. 기존 필수/선택 분류·운동 기록·계정 정보는 유지합니다.

`import-fitness-grades.js`는 연도별 학생명단 파일의 2026년 행을 학번·이름·학년·반으로 정확히 연결합니다. 2025년 자료와 분류용 중복 시트는 원본 보관에만 포함하고 이름이나 진급 추정으로 학생에게 연결하지 않습니다. 원본 전체 시트 값과 해시, 학생별 출처는 비공개 DB에 보관합니다.

```sh
# 기본은 읽기 전용 검증. --include-existing은 이전에 보존된 2026년 원본으로 누락 학생을 보완합니다.
node --env-file=backend/.env backend/scripts/import-fitness-grades.js path/to/grades.xlsx --dry-run
node --env-file=backend/.env backend/scripts/import-fitness-grades.js path/to/grades.xlsx --include-existing --dry-run
# 반영 범위를 확인하고 DB를 백업한 뒤, 같은 옵션에 --apply로 실행합니다.
node --env-file=backend/.env backend/scripts/import-fitness-grades.js path/to/grades.xlsx --include-existing --apply
```

일치하지 않는 학생이나 기존 원본과 충돌하는 평가 값이 있으면 전체 반영을 중단합니다. 같은 파일을 다시 반영해도 평가 이력·원본 행을 중복 생성하지 않습니다. 학생 ID·비밀번호·세션·참여 여부·운동 기록은 갱신하지 않습니다. 새 자료가 없는 학생은 임의의 등급을 지정하지 않고 미등록으로 표시합니다.

## 확인 대기와 의존성 점검

레거시 2026 챌린지의 12주차 덤벨은 사용자가 승인한 파일 기준을 적용합니다. 8/31~9/4의 각 날짜에 컬·스쿼트·로우 3종목 모두 10회×2세트를 충족하면 완료일이며, 완료일 3일 이상이면 해당 주차 완료입니다. 종목별 세트 수를 JSON으로 보존하고 미입력과 0세트를 구분합니다. 레거시 전체 12주를 모두 완료하면 전체 완료로 판정합니다. 새 챌린지는 자신에게 설정된 주차 수와 운동 목표로 집계하며, 덤벨 종목 ID·세트 목표도 해당 주차 정의를 사용해요. 외부 배포 주소·보관 기간은 사용자가 정한 값을 사용해야 합니다.

2026-10-20 의존성 점검에서 런타임의 업로드·파일 판별·로그인 속도 제한 관련 보안 수정 버전으로 갱신했습니다. [Express 업로드 보안 공지](https://expressjs.com/en/blog/2026-08-31-security-releases/), [Multer 2.4.0 릴리스](https://github.com/expressjs/multer/releases/tag/v2.4.0)

`npm audit`의 잔여 항목은 숨기지 않습니다. Prisma 6 CLI 개발 의존성의 `deepmerge-ts`/`effect`에는 경고가 있으며 Prisma 7 전환은 별도 호환성 작업입니다. 서비스 요청 경로는 Prisma Client를 사용하고 외부 입력을 CLI 설정 병합이나 Effect RPC로 전달하지 않습니다. ExcelJS의 전이 의존성 `uuid` 경고는 v3/v5/v6의 사용자 지정 버퍼 경로에 관한 것으로, 이 프로젝트와 ExcelJS에서 확인한 호출은 버퍼를 전달하지 않는 v4입니다. 이 범위 확인은 경고가 해결되었다는 뜻이 아니므로 배포 전 다시 점검해야 합니다.

## 교사의 학생 비밀번호 관리

명단과 학생 상세의 **비밀번호 관리**에서 변경 여부, 초기·임시 비밀번호 확인, 비밀번호 초기화를 사용할 수 있어요. 학생이 직접 정한 비밀번호는 확인할 수 없고, 변경 완료 이후에는 보관한 임시 비밀번호를 제거해요. 초기화하면 모든 기존 학생 세션이 종료돼요.

발급한 임시 비밀번호는 AES-256-GCM으로 암호화하며 각 비밀번호 해시에 묶어요. DB에는 암호문만 저장하고 로그인에는 기존 scrypt 해시를 사용해요. 목록·학생 응답에는 암호문이나 비밀번호를 포함하지 않으며, 교사가 확인 버튼을 눌렀을 때만 교사 전용 API에서 반환해요. 응답 캐시와 브라우저 영구 저장소에는 보관하지 않아요.

배포 시 마이그레이션과 `TEMPORARY_PASSWORD_KEY`(32바이트 랜덤 키를 표현한 64자리 hex)가 필요해요. `npm run setup` / `npm run dev`는 키가 없는 로컬 `backend/.env`에 한 번 생성해요. 서버에서는 비밀 환경 변수로 공급하거나, `backend/.env` 준비 후 `node scripts/setup-password-vault.mjs`로 생성하세요. 생성된 키는 DB와 별도로 비공개 백업해야 하며 재배포 때 유지하세요. 키를 바꾸면 이전 임시 비밀번호를 확인할 수 없어요. 키를 Git이나 DB ZIP에 넣지 마세요.

이전 계정은 보관본이 없으면 초기화로 새 비밀번호를 발급할 수 있어요. 기존의 비공개 초기 발급 원본이 있는 경우 아래 도구는 이름·학번과 현재 비밀번호 해시가 일치하며 아직 변경하지 않은 학생만 보완해요. 기존 비밀번호·세션·발급 시각은 바꾸지 않아요.

```sh
node --env-file=backend/.env backend/scripts/recover-temporary-passwords.js /private/accounts.private.json --dry-run
node --env-file=backend/.env backend/scripts/recover-temporary-passwords.js /private/accounts.private.json --apply
```

운영 서버에서 환경 키를 지정하지 않으면 서버 시작 시 `STORAGE_DIR/.secrets/temporary-password.key`에 키를 한 번 생성하고 재사용해요(파일 0600, 디렉터리 0700). 새 릴리스 폴더가 아니라 기존 영속 `STORAGE_DIR` 안에 있으므로 자동 배포·재시작에도 유지돼요. `TEMPORARY_PASSWORD_KEY_FILE`로 별도 영속 파일을 지정할 수도 있어요. 기존 키를 다른 키로 교체하지 말고 비공개로 백업하세요. 이 파일은 첨부 DB 레코드와 연결되지 않아 첨부 조회 API로 받을 수 없어요.
