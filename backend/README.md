# Self Fit 백엔드

Express + PostgreSQL + Prisma로 실제 계정·운동 기록·정정·첨부·알림을 저장합니다. API 계약은 [API.md](./API.md), 운동 집계 규칙은 [src/domain/index.js](./src/domain/index.js)에 있습니다.

## 로컬 실행

프로젝트 루트에서 실행합니다. Node.js 22.12 이상, PostgreSQL, 영상 검사용 `ffprobe`가 필요합니다. 영상 회귀 테스트에는 `ffmpeg`도 사용하며, 없으면 영상 길이 검사만 건너뜁니다(`FFMPEG_PATH`로 경로 지정 가능).

```sh
npm install
npm run setup
npm run dev
```

`setup`은 프로젝트 전용 PostgreSQL 시작, Prisma Client 생성, 마이그레이션 적용을 수행합니다. 학생이나 예시 활동 기록을 생성하지 않습니다. 기본 프런트엔드는 `http://127.0.0.1:5173`, API는 `http://127.0.0.1:4000/api`입니다. 프런트엔드 개발 서버가 `/api`를 프록시합니다.

이미 준비된 DB에서 백엔드만 실행하려면 루트에서 다음을 사용합니다.

```sh
npm run db:deploy --workspace backend
npm run start --workspace backend
```

`GET /api/health`의 `database: "ready"`가 DB 연결 성공을 뜻합니다. 운영 서버는 시스템의 실제 한국 날짜를 사용합니다. 날짜를 되돌리는 환경 변수나 HTTP API는 없습니다. 2026년 9월 4일 이후 신규 활동 입력과 운동 독려는 닫히며 기존 기록 조회와 정정 절차는 유지됩니다.

## 실제 교사 계정 생성

교사 계정은 자동 생성하지 않습니다. DB 준비 후 터미널에서 실행하세요.

```sh
npm run bootstrap-teacher --workspace backend
```

본인의 로그인 ID와 이름, 비밀번호를 직접 입력합니다. 비밀번호와 확인 입력은 화면에 표시되지 않으며 로그에 남기지 않습니다. 비밀번호는 영문·숫자를 포함한 8~128자이고 로그인 ID와 달라야 합니다. Ctrl+C로 취소하면 계정을 만들지 않습니다. 교사 계정이 이미 있으면 덮어쓰지 않고 종료합니다.

자동화가 필요한 경우 `TEACHER_ID`, `TEACHER_NAME`, `TEACHER_PASSWORD` 환경 변수 또는 `studentNumber`, `name`, `password` 필드의 JSON 객체를 표준입력으로 전달할 수 있습니다. 비밀번호를 CLI 인수에 넣지 마세요. 표준입력 JSON은 전달한 필드에 한해 환경 변수보다 우선합니다. 명령 성공 시 비밀번호를 출력하지 않습니다.

학생은 교사 로그인 후 명단 화면에서 실제 명단으로 등록합니다. 엑셀은 먼저 검증하며, 교사가 등록을 실행해야 저장됩니다. 등록·초기화에서 발급한 개인별 임시 비밀번호는 해당 응답에서 한 번만 제공하며 서버는 해시만 저장합니다.

## 환경 설정

백엔드는 `backend/.env`를 읽습니다. 루트의 DB 도구가 만든 로컬 설정을 사용할 수 있습니다. 이 파일과 DB·첨부 폴더는 버전 관리하거나 웹 정적 폴더에 넣지 않습니다.

| 변수 | 용도 |
| --- | --- |
| `DATABASE_URL` | 실제 서비스 전용 PostgreSQL 연결 |
| `TEST_DATABASE_URL` | 이름이 `_test`로 끝나는 별도 테스트 DB 연결 |
| `APP_ORIGIN` | 허용하는 프런트엔드 origin. 기본 `http://localhost:5173`, 여러 주소는 쉼표 구분 |
| `HOST`, `PORT` | API 주소. 기본 `127.0.0.1`, `4000` |
| `STORAGE_DIR` | 공개 웹 경로 바깥의 첨부 저장 폴더 절대 경로 |
| `FFPROBE_PATH` | 필요할 때 지정하는 `ffprobe` 실행 파일 경로 |
| `FFMPEG_PATH` | 영상 회귀 테스트가 사용하는 `ffmpeg` 경로. 없으면 영상 길이 검사만 건너뜁니다 |
| `TRUST_PROXY` | 리버스 프록시 뒤에서 실제 접속 주소를 보도록 하는 Express trust-proxy 값(`1`, `true`, `loopback`, 주소 목록) |
| `NODE_ENV` | HTTPS 운영 환경에서 `production`으로 설정하면 세션 쿠키에 `Secure` 적용 |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` | 웹 푸시를 실제 사용할 때 운영자가 지정하는 키와 연락 URI |

로그인 실패는 계정당 15분에 10회, 접속 주소당 300회까지 허용하며 성공한 로그인은 세지 않습니다. 학교처럼 한 공인 IP를 공유하는 환경에서도 한 명의 실패가 다른 사람을 막지 않습니다. 프록시 뒤에서는 `TRUST_PROXY`를 설정해야 주소 단위 제한이 실제 클라이언트를 봅니다.

세션은 PostgreSQL에 저장하고 브라우저에는 HttpOnly·SameSite 쿠키만 제공합니다. 세션은 8시간 후 만료됩니다. 비밀번호 초기화는 학생의 모든 세션을 폐기합니다. 본인 학생과 총괄 교사만 첨부를 읽을 수 있으며 경로를 알아도 권한 검사를 거칩니다.

사진은 기록당 3장/각 10MB, 영상은 1개/100MB/60초까지입니다. 파일 내용을 검사하고 영상 길이는 `ffprobe`로 확인합니다. 당일 권한 확인을 통과해 시작한 업로드는 자정을 넘어 끝나도 같은 요청을 마무리할 수 있습니다. 기한 후 새로 시작하는 업로드·삭제는 거부됩니다. 파일 실패는 이미 저장된 운동 기록을 취소하지 않습니다.

명단 XLSX는 5MB까지 받으며 압축 해제 총량도 50MB로 제한합니다. 실제 셀의 수식·링크는 명단 값으로 가져오지 않습니다. 내보내기의 이름·학번·사유는 수식이 아닌 텍스트 셀로 저장합니다. 운영 첨부와 기록의 자동 삭제·보관 기간은 설정하지 않았습니다.

## 알림과 푸시

앱 안 알림은 웹 푸시 설정 없이 작동합니다. 운동 독려는 한국 시간 20시 이후 해당 활동일의 참여·주간 완료·입력 상태·주말 설정을 확인합니다. `(학생, 날짜, 운동 독려)` 이벤트는 DB 고유 키로 한 번만 생성합니다. 정정 처리 알림은 프로그램 종료 후에도 남습니다.

실제 휴대폰 푸시를 운영하려면 운영자가 VAPID 키·연락 URI를 정하고 위 세 변수를 모두 설정한 뒤 서버를 재시작합니다. 키를 임의 생성하거나 연락처를 추정해 설정하지 않습니다. 학생이 브라우저 알림을 허용하고 구독해야 전달할 수 있습니다. 아이폰은 홈 화면에 추가한 웹앱 흐름을 사용합니다. [WebKit 공식 안내](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)

푸시 실패는 같은 앱 알림 이벤트에서 최대 5회 재시도합니다. 성공한 구독에는 재시도를 생략하며 서비스 워커는 이벤트 ID를 알림 태그로 사용합니다. 만료된 구독은 제거합니다. 현재 VAPID가 미설정이면 실제 푸시 수신은 검증된 상태가 아니며, 앱 안 알림과 이벤트 생성·중복 방지는 별도로 검증할 수 있습니다.

운동 독려는 실제 기기로 보내기 직전에 조건을 다시 확인합니다. 그사이에 주간 목표나 당일 목표를 채웠거나 날짜가 지났으면 대기 중인 독려 푸시를 취소합니다. 앱 안의 과거 이벤트는 보존하며, 정정 결과 알림은 이 제한을 적용하지 않습니다.

## 테스트

루트에서 실행합니다.

```sh
npm test
npm run test:integration --workspace backend
```

도메인 테스트는 DB 없이 동작합니다. 통합 테스트는 `TEST_DATABASE_URL`이 있을 때만 실행하며 DB 이름의 `_test` 접미사를 강제합니다. 실행마다 임의의 별도 스키마와 임시 첨부 폴더를 만들고 마이그레이션을 적용한 후 정리합니다. 테스트용 계정·활동은 그 스키마 안에만 생성합니다. 운영 DB에 테스트 명단이나 시연 데이터를 넣지 않습니다.

통합 테스트는 인증·역할 권한, 첫 비밀번호 변경, 임시 비밀번호 초기화와 세션 폐기, 실제 종료일 제한, 정정 전후 값·이력·낙관적 충돌, 명단 검증/등록, 비공개 첨부·60초 영상 검사, 알림 중복 방지, 엑셀 의미 보존을 확인합니다. 당일 입력 회귀만 테스트 프로세스의 시계를 가짜 시각으로 제어하며 실제 서버의 날짜 기능을 변경하지 않습니다.

## 확인 대기와 의존성 점검

12주차 덤벨은 사용자가 승인한 파일 기준을 적용합니다. 8/31~9/4의 각 날짜에 컬·스쿼트·로우 3종목 모두 10회×2세트를 충족하면 완료일이며, 완료일 3일 이상이면 해당 주차 완료입니다. 종목별 세트 수를 JSON으로 보존하고 미입력과 0세트를 구분합니다. 전체 12주를 모두 완료하면 전체 완료로 판정합니다. 외부 배포 주소·보관 기간은 사용자가 정한 값을 사용해야 합니다.

2026-10-20 의존성 점검에서 런타임의 업로드·파일 판별·로그인 속도 제한 관련 보안 수정 버전으로 갱신했습니다. [Express 업로드 보안 공지](https://expressjs.com/en/blog/2026-08-31-security-releases/), [Multer 2.4.0 릴리스](https://github.com/expressjs/multer/releases/tag/v2.4.0)

`npm audit`의 잔여 항목은 숨기지 않습니다. Prisma 6 CLI 개발 의존성의 `deepmerge-ts`/`effect`에는 경고가 있으며 Prisma 7 전환은 별도 호환성 작업입니다. 서비스 요청 경로는 Prisma Client를 사용하고 외부 입력을 CLI 설정 병합이나 Effect RPC로 전달하지 않습니다. ExcelJS의 전이 의존성 `uuid` 경고는 v3/v5/v6의 사용자 지정 버퍼 경로에 관한 것으로, 이 프로젝트와 ExcelJS에서 확인한 호출은 버퍼를 전달하지 않는 v4입니다. 이 범위 확인은 경고가 해결되었다는 뜻이 아니므로 배포 전 다시 점검해야 합니다.
